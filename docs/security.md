# 인증 서비스 보안 정책

## 비밀번호와 로그인

- 비밀번호는 15~64자이며 문자 종류의 조합을 강제하지 않는다. 공백, 한글, Unicode, 이모지를 허용한다. 제어 문자, 공백만으로 이뤄진 값, 취약·유출 비밀번호는 거부한다. 복사·붙여넣기와 자동 완성을 허용한다.
- 비밀번호마다 무작위 Salt를 생성하고 Argon2id로 해싱한다. 로그인에 성공한 뒤 기존 해시가 현재 정책에 맞지 않으면 재해싱한다. 길이 산정, Unicode 처리, Argon2id 파라미터와 취약·유출 비밀번호 확인 방식은 미결정이다.
- 존재하지 않는 아이디에도 더미 해시를 검증해 시간 차이를 줄인다. 아이디 미존재와 비밀번호 불일치에 동일한 외부 오류를 반환한다.
- Redis 기반 요청 제한을 적용한다. 적용 대상별 제한 값, 집계 기준과 Redis 장애 시 동작은 미결정이다.

## 토큰과 서비스 신뢰

- Auth Service가 로그인 성공 후 JWT를 발급한다. Gateway는 서명과 필수 클레임을 검증하고 사용자 ID를 전달한다. 유효성을 확인할 수 없는 보호 요청은 거부한다.
- Refresh Token을 사용한다. Rotation 적용 여부, 토큰 수명, 동시 갱신·재사용 정책은 팀 논의 후 정한다.
- 로그아웃·비밀번호 재설정·회원 탈퇴 후 기존 Access Token과 Refresh Token을 즉시 무효화할지, 무효화 범위와 Gateway의 폐기 상태 확인 방식은 팀 논의 후 정한다. 탈퇴한 계정은 즉시 새 로그인을 차단한다.
- 대상 서비스는 전달받은 ID로 접근 권한을 확인한다. 허용할 호출 경로가 확정되면 호출자 신원 확인 방식과 전달된 ID의 신뢰 조건을 정한다. 외부가 제시한 ID와 허용된 경로를 우회한 요청의 처리도 정한다.
- 키 소유자, 설정 주입, 정상 교체 및 긴급 폐기 절차를 정한다. 허용 알고리즘, 발급자·대상, 검증 실패 처리도 함께 정한다.

## 이메일 인증과 민감 데이터

- 이메일 인증번호와 만료 정보는 Redis에서 관리한다. 유효기간, 재발급, 검증 시도 제한 및 재사용 처리 기준은 미결정이다.
- 평문 비밀번호, 토큰, 인증번호, 비밀키를 코드·로그·공유 문서에 남기지 않는다. 감사 이벤트, 접근 권한과 보존 기간을 정한다.

### 보호자 가입용 이메일 증명

- 인증번호 검증 성공 시 해당 이메일과 보호자 가입 목적에 묶인 만료 가능한 일회용 증명값을 발급한다. 가입 시 요청 이메일과의 일치, 유효기간, 사용 여부를 검증한다. 가입에 사용된 증명값으로 다른 가입을 완료할 수 없다.
- 인증번호와 가입 증명값의 수명은 각각 결정한다. 발송·재발급·검증 시도 제한과 증명 상태의 저장 위치 및 처리 실패 시 재시도 규칙도 정한다.
- 가입 증명값을 로그에 남기지 않는다.

## JWKS 채택 시 결정할 항목

- 키 배포 방식과 신뢰할 JWKS 주소를 정한다. 이전 키가 필요한 기간은 토큰 수명, 허용 시계 오차, 배포 전파 지연을 반영한다.
- 캐시 유효기간은 정상 교체와 긴급 폐기의 허용 지연, JWKS 장애 시 가용성 목표, 검증 인스턴스 수와 재조회 부하를 기준으로 결정한다.
- 알 수 없는 키 ID, 캐시 만료, 조회 실패 시 재조회·동시 요청·접근 거부 기준을 정한다. 긴급 폐기 시 캐시 무효화 필요성을 확인한다.
