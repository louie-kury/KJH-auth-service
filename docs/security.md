# 인증 서비스 보안 정책

## 비밀번호와 로그인

- 비밀번호는 15~64자이며 문자 종류의 조합을 강제하지 않는다. 공백, 한글, Unicode, 이모지를 허용한다. 제어 문자, 공백만으로 이뤄진 값, 취약·유출 비밀번호는 거부한다. 복사·붙여넣기와 자동 완성을 허용한다.
- 비밀번호마다 무작위 Salt를 생성하고 Argon2id로 해싱한다. 로그인에 성공한 뒤 기존 해시가 현재 정책에 맞지 않으면 재해싱한다. 길이 산정, Unicode 처리, Argon2id 파라미터와 취약·유출 비밀번호 확인 방식은 미결정이다.
- 존재하지 않는 아이디에도 더미 해시를 검증해 시간 차이를 줄인다. 아이디 미존재와 비밀번호 불일치에 동일한 외부 오류를 반환한다.
- Redis 기반 요청 제한을 적용한다. 적용 대상별 제한 값, 집계 기준과 Redis 장애 시 동작은 미결정이다.

## 토큰과 서비스 신뢰

- Auth Service가 로그인 성공 후 JWT를 발급한다. Gateway는 서명과 필수 클레임을 검증하고 사용자 ID를 전달한다. 유효성을 확인할 수 없는 보호 요청은 거부한다.
- Refresh Token을 사용한다. Rotation 적용 여부, 토큰 수명, 동시 갱신·재사용 정책은 팀 논의 후 정한다.
- 로그아웃·비밀번호 재설정·회원 탈퇴 후 기존 Access Token과 Refresh Token을 즉시 무효화할지, 무효화 범위와 Gateway의 폐기 상태 확인 방식은 팀 논의 후 정한다. 탈퇴한 계정은 즉시 새 로그인을 차단한다.
- 대상 서비스는 전달받은 ID로 접근 권한을 확인한다. 허용할 호출 경로가 확정되면 호출자 신원 확인 방식과 전달된 ID의 신뢰 조건을 정한다. 외부가 제시한 ID와 허용된 경로를 우회한 요청의 처리도 정한다.
- 키 소유자, 설정 주입, 정상 교체 및 긴급 폐기 절차를 정한다. 허용 알고리즘, 발급자·대상, 검증 실패 처리도 함께 정한다.

## 이메일 인증과 민감 데이터

- 평문 비밀번호, 토큰, 인증번호, 비밀키를 코드·로그·공유 문서에 남기지 않는다. 감사 이벤트, 접근 권한과 보존 기간을 정한다.

### 보호자 가입용 이메일 인증

- 주소 앞뒤의 공백을 제거하고 도메인만 소문자로 변환한다. ASCII 이메일 주소를 지원하고 내부 공백, 제어 문자, 전각 문자는 거부한다. 로컬 파트의 대소문자, `+tag`, 점을 보존한다. 가입에서도 같은 정규화와 비교 기준을 사용한다.
- 인증번호는 안전한 난수로 생성한 숫자 6자리다. Redis에 이메일에 묶인 코드의 HMAC과 발급 ID, 시도 횟수, 만료 정보를 저장한다. Brevo API 접수 후 코드가 활성화되고 5분간 유효하다.
- 동일 이메일의 발송 예약을 직렬화한다. 새 발송을 Brevo API에서 접수하면 새 코드를 활성화하고 이전 코드를 폐기한다. 발송 실패 시 새 예약을 해제하고 아직 유효한 기존 코드를 유지한다. 늦게 도착한 발송 결과는 해당 발급 ID가 현재 예약일 때만 반영한다.
- 현재 코드 확인, 검증 실패 횟수 갱신, 검증 성공 시 코드 소비를 Redis에서 원자적으로 처리한다. 동일 코드의 동시 검증 요청에서는 한 건만 증명값 발급으로 진행한다.

| 구분 | 제한 |
| --- | --- |
| 이메일별 발송 | 최소 60초 간격, 최근 1시간 최대 5회 |
| IP별 발송 | 최근 1시간 최대 30회 |
| 서비스 전체 발송 | 최근 1분 최대 100회 |
| 코드별 검증 실패 | 다섯 번째 불일치에서 해당 코드 무효화 |
| 이메일별 검증 실패 | 최근 1시간 최대 10회 |
| IP별 검증 요청 | 최근 1분 최대 60회 |

- 제한 확인과 카운터 갱신을 Redis에서 원자적으로 처리한다. 예약에 성공한 발송 요청은 Brevo API가 실패해도 발송 한도에 반영한다. 코드를 재발급해도 이메일·IP 한도를 유지한다.
- [Gateway 내부 인터페이스](api.md#gateway-내부-인터페이스)에 따라 클라이언트 IP를 확인한다. Redis 장애 시 발송과 검증 요청을 차단하고 `503`을 반환한다.

### 보호자 가입용 이메일 증명

- 인증번호 검증 성공 시 32바이트 난수로 발급한 증명값을 인증 이메일과 보호자 가입 목적에 묶는다. 유효기간은 10분이다. Redis에 증명값 해시를 키로 이메일과 목적을 TTL 10분으로 저장한 후 원본을 응답한다.
- 코드 소비 후 증명 저장이 실패하면 `503`을 반환한다. 재발송이 허용되는 시점에 새 코드를 요청한다.
- 증명값 검증과 소비는 후속 보호자 가입(AUTH-005)에서 처리한다. 가입 시 이메일과 목적 일치 여부, 만료와 소비 여부를 확인한다. 증명값 소비 후 가입 데이터 저장 실패 또는 Redis 증명 유실 시 재인증한다.
- 가입 증명값을 로그에 남기지 않는다. Brevo API 발송과 Redis 처리 실패는 내부에서 구분한다.

## JWKS 채택 시 결정할 항목

- 키 배포 방식과 신뢰할 JWKS 주소를 정한다. 이전 키가 필요한 기간은 토큰 수명, 허용 시계 오차, 배포 전파 지연을 반영한다.
- 캐시 유효기간은 정상 교체와 긴급 폐기의 허용 지연, JWKS 장애 시 가용성 목표, 검증 인스턴스 수와 재조회 부하를 기준으로 결정한다.
- 알 수 없는 키 ID, 캐시 만료, 조회 실패 시 재조회·동시 요청·접근 거부 기준을 정한다. 긴급 폐기 시 캐시 무효화 필요성을 확인한다.
