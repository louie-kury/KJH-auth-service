# 가입용 이메일 증명값을 Redis에 저장

상태 — 승인됨

## 배경

AUTH-006은 이메일 인증 성공 후 보호자 가입에 사용할 만료 가능한 일회용 증명값을 발급한다. 인증번호와 요청 제한은 이미 Redis에서 관리한다. AUTH-005는 증명값을 확인하고 소비한 뒤 MySQL에 가입 정보를 저장한다.

## 결정

증명값 원본 대신 SHA-256 해시를 Redis 키로 사용하고, 인증 이메일과 가입 목적을 10분 TTL로 저장한다. AUTH-005는 입력 검증 후 증명값을 원자적으로 확인·소비한다. 증명값이 유실되거나 소비 후 가입 저장에 실패하면 이메일을 다시 인증한다.

## 검토한 대안

증명값을 MySQL에 저장하면 가입 저장과 증명 소비를 같은 트랜잭션에서 처리할 수 있다. 저장 실패 시 유효한 증명으로 다시 시도할 수 있지만 별도 테이블과 마이그레이션, 만료 데이터 정리가 필요하다.

## 선택 이유와 영향

증명값은 짧은 수명의 임시 데이터다. 기존 Redis의 TTL을 사용하면 별도 테이블과 정리 작업을 줄일 수 있다. Redis와 MySQL은 하나의 트랜잭션으로 묶이지 않으므로 저장 실패나 Redis 유실 시 사용자가 재인증해야 한다. 증명값 소비와 가입 저장은 후속 AUTH-005에서 구현한다.
